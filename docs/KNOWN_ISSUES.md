# 已知问题与适用范围

> 这份清单只写**真实存在**的限制。没有验证过的功能一律标为"未验证"，
> 不做"应该没问题"的推断。

---

## 1. 适配范围（重要，请先读这一节）

本程序**不是"所有高校通用"的认证客户端**。当前确认可用与未验证的边界如下。

| 认证方式 | 状态 | 说明 |
| --- | --- | --- |
| Dr.COM / 哆点 ePortal（`drcom:plain-yau`） | **已在模拟门户上端到端验证通过**；开发期间真实环境日志也显示成功 | 需要门户是 Dr.COM 内核；`login_method` 由门户配置接口自动获取 |
| Dr.COM AES 加密接口（`drcom:eportal-aes`） | 代码完整，**未在真实环境确认成功** | 报文按门户 JS（a40/a41.js）复刻，并用 FIPS-197 向量 + CryptoJS 逐字节比对验证过算法 |
| 通用 HTML 表单（用户名 + 密码 + 提交按钮） | 逻辑完备，本机模拟门户已验证；**未在多所学校验证** | 覆盖"一个 form 两大输入框"这类最常见门户 |
| 需要 JavaScript 加密参数的门户（Srun/深澜等） | **不支持全自动** | 只能用浏览器模式人工完成；`custom` 接口可人工配置 |
| 需要验证码的门户 | **不支持全自动**（设计上拒绝绕过） | 浏览器模式会停下并把窗口留给用户 |
| 需要客户端软件 / 802.1X 认证 | **不支持** | — |
| 浏览器模式（CDP 注入填写） | **源码模式已端到端验证通过**（真实 Edge 155，含协议勾选、运营商选择、origin 拒绝、两阶段来源校验、窗口清理）。**打包 EXE 形态未完成端到端验证**：开发会话里打包进程被令牌限制，Edge 渲染进程起不来（`Target crashed`），需在普通桌面验收 | 见 `docs/AUDIT_V3.md` 第 13 节 |

结论：**先看清楚自己学校是哪种认证**。无法识别时程序会明确说"没找到登录表单"并给出
页面标题与疑似接口，而不会假装成功。

---

## 2. 功能限制

1. **不能绕过验证码或学校的访问控制**。遇到验证码会停在人工步骤，这是设计约束。
2. **不修改 Wi-Fi 安全配置**。除"开放网络没有已保存配置时临时建一个"之外，
   不创建/覆盖任何无线配置文件；需要密码的网络必须先在 Windows 里连一次。
3. **不做多账号管理**。一个配置对应一个账号。
4. **不支持代理上网**。程序默认绕开系统代理（否则探测会被代理接走，
   出现"没认证却显示在线"），所以依赖代理才能出网的环境无法使用。
5. **DPAPI 密文与本机 + 当前 Windows 用户绑定**。换电脑、换用户、重装系统后
   必须重新输入密码（程序会明确提示，不会静默失败）。

## 3. 已知问题（技术性）

| 编号 | 问题 | 影响 | 现状 / 变通 |
| --- | --- | --- | --- |
| K-00 | **界面打开几秒后自己消失（进程崩溃，不是关闭）** | 完全无法使用图形界面 | **已定位并已在 3.0.4/3.0.5 处理**：第三方"叠加类"软件注入的 DLL 与 tkinter 冲突。本机实测为**游戏加加（GamePP）**的 `GPP64.dll`：崩溃代码 `0xc0000005`，且**仅 20 行的最小 tkinter 程序同样崩溃**，退出游戏加加后 GUI 稳定运行。V3.1.0 起**默认不再施加进程缓解策略**（实测 `MicrosoftSignedOnly` 会连带拒绝本程序自带的 PSF 签名组件，是「部分功能损坏」的根因；若需加固可显式设 `CAMPUSNET_HARDEN=1`），实测远程注入的 `LoadLibraryW` 返回 0（加载被拒绝）、DLL 未进入进程；V3.0.5 起再抑制"损坏的映像 0xc0000428"弹窗。若你仍遇到确认问题：退出游戏加加，或在其设置里把 `CampusNet.exe` 加入排除。诊断命令：`CampusNetCLI.exe conflicts` |
| K-00b | **弹窗「损坏的映像 / 错误状态 0xc0000428」** | 界面被模态框挡住，看起来像出错 | **这是加固生效的证据**：`0xc0000428` = `STATUS_INVALID_IMAGE_HASH`，表示游戏加加的 `GPP64.dll` 因签名策略被系统拒绝加载（以前这一步是直接把进程打崩）。V3.0.5 起本进程用 `SetErrorMode(SEM_FAILCRITICALERRORS)` 抑制此类弹窗，注入仍被拒绝但不再打扰用户 |
| K-01 | **受限会话**（沙箱 / AppContainer / 受管企业环境）可能不给未签名 EXE 写注册表或 `%LOCALAPPDATA%` 的权限 | 开机自启动开关可能报"拒绝访问"；数据目录可能建不出来 | 这是环境策略不是程序缺陷：普通用户桌面下 `HKCU\\...\\Run` 与 `%LOCALAPPDATA%` 都是用户可写的。程序会给出"无法写入开机自启动项：…"的可读提示，其余功能不受影响 |
| K-02 | **看不到附近的 Wi-Fi 列表** | 只能在「设置」里手动填写 SSID（不影响认证） | Windows 把 WLAN 信息归为**位置相关数据**：位置服务被关掉时，`netsh wlan` 会直接返回"此 shell 命令需要位置权限…"。V3.0.3 起优先用 **Windows 原生 WLAN API**（结构化数据，不受本地化文本影响），并会把这类系统限制翻译成你要点的开关路径（设置 → 隐私和安全性 → 位置 → 位置服务 + 让桌面应用访问你的位置）。诊断命令：`CampusNetCLI.exe wifi` |
| K-03 | **点了开机自启但后台守护没起来** | 自动重连不生效 | 最常见原因是**配置里的密码在本机解不开**（换过 Windows 用户 / 换过电脑）：守护进程会立即退出。V3.0.3 起界面会直接说"后台守护启动失败：配置里的密码在本机解不开…请重新输入一次上网密码"，设置页也会在密码框下方标红提示。处理办法：重新输入一次上网密码并保存 | **3.1.0 修复的两个真实缺陷**：① 用户点过「停止」后进程被强杀，`stop.flag` 会留在数据目录，下次守护启动看到它就立即退出（退出码 0、无心跳）——现在启动前会清理遗留标记；② 运行锁是全局命名对象，属于另一个数据目录/旧版本的实例能永久占锁（界面一直显示「运行中但无响应」）——现在互斥体名带数据目录指纹，互不干扰。排查命令：`CampusNetCLI.exe daemon` 会打印进程/心跳/状态与判断依据。
| K-16 | 门户跳转到**另一个域名**时，浏览器模式会停止自动填写 | 需要用户手动完成或在设置里更新认证页地址 | 这是刻意的安全行为（不把密码填到未确认页面）；提示里说明了怎么处理 |
| K-17 | 学校认证接口与认证页不同域名时，通用表单提交会被拒绝（`refused-target`） | 认证失败 | 在 `config.json` 的 `trusted_auth_hosts` 里加入接口域名即可 |
| K-18 | 浏览器模式下，登录表单的 `action` / 按钮 `formaction` 指向白名单外的主机时会停止填写（状态 `wrong-form-action`） | 认证失败 | 与 K-17 同一套判据：确认那是学校自己的认证接口后，把该主机加入 `trusted_auth_hosts`。**3.1.2 起**浏览器模式也执行这条校验：此前只校验页面 origin，表单 action 指向别处时凭据仍会被提交过去 |
| K-04 | 自签证书门户在默认配置下认证失败（`tls-error`） | 认证失败 | 把门户地址加入 `tls_insecure_hosts`，或在设置里按提示放行 |
| K-05 | 门户若要求"必须先访客登录/选择套餐"等前置流程，HTTP 直连无法完成 | 需要人工 | 用浏览器模式人工完成一次 |
| K-06 | 计划任务方式已被移除，只保留 HKCU Run 自启动 | 守护进程崩溃后不会由系统"每 15 分钟"拉起 | 守护进程本身是不死循环（所有异常就地捕获）；界面读心跳可发现并在设置页一键启动 |
| K-07 | 旧版本地日志/转储文件仍留在原项目目录（未删除） | 占用磁盘、含历史个人数据 | 按"不删用户数据"的要求予以保留；这些文件不会进发布包与版本控制 |
| K-08 | 便携模式（`portable.txt`）下数据写在程序目录 | 若程序目录只读会自动回落到 `%LOCALAPPDATA%` | 已实现回落逻辑 |
| K-09 | 打包体积约 33 MB | 下载体积偏大 | onedir 形态的固有代价；未使用 UPX（会显著增加误报率） |
| K-10 | 通知推送（webhook）为可选功能，消息内容未经第三方审计 | 仅影响用户自己的机器人 | 默认关闭；消息不含账号密码 |
| K-11 | 无版本号的旧配置每次启动都会被判定为"需要迁移"（并做一次内容去重后的备份） | `backup/` 目录里会有一份 `config.v1.*.json` | 已按内容哈希去重并限制最多 5 份；只要用户在界面里保存一次配置，就会写入版本号、此后不再迁移 |
| K-12 | 浏览器模式需要本机装有 Edge 或 Chrome | 极少数精简系统没有 | 找不到时会明确提示"未找到 Edge 或 Chrome"；可用 `CAMPUSNET_BROWSER` 指定路径 |
| K-13 | 联网探测只用 3 个**依赖 DNS** 的固定域名，没有 IP 直连兜底 | 校园网"先拦 DNS"时三个目标会全部 `dns-error`，此时**自动探测不到门户**（本机日志里 `dns-error` 真实出现过） | **3.1.1 起**这类情况会明确显示「无法确定认证状态」并引导在「设置」里手工填写地址，**不会**误报"已找到门户"。彻底解决需要增加 IP 直连探测目标，属于独立评估项，本版未改探测目标集合 |
| K-14 | `checker.check()` 仍把"探测目标返回 200 + HTML"判为内容劫持，后台守护据此会尝试一次认证 | 极少数情况下多一次无意义的认证尝试 | **不会泄露凭据**：`UrlPolicy` 在提交前校验目标主机（非认证页主机且不在 `trusted_auth_hosts` 就拒绝），且页面找不到登录表单会立即停止。3.1.1 起「探测/引导」路径已要求**正向门户证据**才认门户；守护的触发条件按原设计保留（避免漏掉纯 JS 渲染的门户） |
| K-15 | 3.1.0 的探测结果曾会把"跟随重定向后的最终页地址"写回 `portal_url`，覆盖掉带网关参数的发现结果 | 门户参数丢失 | **3.1.1 起** `security.keeps_portal_query()` 会在"新地址参数更少"时拒绝覆盖并提示保留原地址 |

## 4. 明确不做的事

- 不关闭、不修改任何安全软件设置（不添加排除项，不关实时保护）。
- 不要求管理员权限（安装、运行、卸载全部是用户级）。
- 不收集遥测、不上传日志；诊断包需要用户自己点击导出并自行决定是否分享。
- 不修改其它程序的配置、启动项或注册表。
- 不删除用户的配置与日志（卸载默认保留，`--remove-data` 才删）。
