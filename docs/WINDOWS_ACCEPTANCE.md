# Windows 验收清单

> 自动化测试只能证明"打包产物能跑起来"。**能不能真的登录你的校园网**必须人工验收。
> 下面每一条都给出"怎么操作 / 怎样算通过 / 不通过怎么排查"。
>
> 建议在一台**没有安装 Python** 的 Windows 上做，这样才能验证"不依赖系统 Python"。
>
> ⚠ **请在普通用户桌面会话里验收**。在沙箱 / AppContainer / 强管控的企业环境里，
> 未签名的 EXE 可能被系统策略禁止写 `HKCU\...\Run` 或 `%LOCALAPPDATA%`，
> 表现为"开机自启动开关报拒绝访问"。那是环境策略，不是本程序的缺陷 ——
> 开发阶段的自动化测试就遇到过这种情况（详见 `docs/AUDIT_V3.md` 第 13 节）。

---

## 0. 准备工作

- [ ] 一台 Windows 10/11 x64，**未安装 Python**
- [ ] 拿到完整的 `CampusNet` 目录（含 `_internal`），不要只复制 EXE
- [ ] 知道自己的校园网 Wi-Fi 名称、上网账号与密码
- [ ] 记录开始时间，最后用来写进验收报告

## 3. 配置与保存

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 3.1 | 在「概览」点「重新扫描」 | 列出附近的 Wi-Fi（名称 + 信号） |
| 3.2 | 「设置」填 Wi-Fi 名称 | 与系统 Wi-Fi 列表一字不差；连接方式选「使用 Windows 已保存的配置」 |
| 3.3 | 点「探测」按钮 | 若当前未认证，自动填入认证页地址；若已在线会提示"当前网络可用" |
| 3.4 | 填账号密码 → 「保存设置」 | 状态栏提示"设置已保存" |
| 3.5 | 查看 `%LOCALAPPDATA%\CampusNet\config.json` | 存在；`username` 是你填的账号；`password_enc` 是长串 base64，**没有明文密码** |
| 3.6 | 再次打开窗口 | 密码框显示「已保存密码；留空表示不修改」 |

## 4. 手动认证

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 4.1 | 断开网络（点击门户注销或断开 Wi-Fi 重连） | — |
| 4.2 | 「认证」页点「直接提交」 | 控制台逐步显示"正在检查…认证页面…"，最终显示认证成功 |
| 4.3 | 浏览器打开任意网站 | 能打开 |
| 4.4 | 故意把密码改错 → 再点「直接提交」 | 提示"账号或密码不正确"；**不会**无限重试 |
| 4.5 | 改回正确密码 | 认证成功 |

**不通过时**：看「设置 → 打开数据目录 → logs」，找出 `状态=` 后面的取值：
`dns-error` / `timeout` = 网络层问题；`redirect` + `refused-target` = 接口域名需要加白名单；
`tls-error` = 自签证书需要放行。

## 5. 浏览器辅助认证（需人工，自动化覆盖不到）

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 5.1 | 断开网络 | — |
| 5.2 | 「认证」页点「打开页面并填写」 | 弹出一个无地址栏的 Edge/Chrome 窗口，加载认证页 |
| 5.3 | 观察行为 | 自动填好账号密码并点击登录（或在需要人工时停下并提示） |
| 5.4 | 若认证页出现验证码 | 程序**停手**并提示需要人工，窗口保留 |
| 5.5 | 认证成功后 | 窗口自动关闭，日志显示认证成功 |
| 5.6 | 故意把认证页地址改成别的域名再试 | 程序拒绝填写并提示"地址与已保存的不一致"（安全行为） |

> 这一节在开发环境（受限沙箱）中**无法执行**，Chromium 启动即退出。必须人工验证。

## 6. 后台守护与自启动

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 6.1 | 「设置」打开「开机自动启动后台守护」 | 提示已开启；顶栏变为「运行中」 |
| 6.2 | 检查注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 有 `CampusNetDaemon`，值指向 `CampusNetService.exe` |
| 6.3 | 注销并重新登录 Windows | 无需打开任何窗口，`CampusNetService.exe` 自动运行 |
| 6.4 | 查看 `%LOCALAPPDATA%\CampusNet\heartbeat.json` | `state` 在 `checking/online/auth` 等之间变化，`updated_at` 在刷新 |
| 6.5 | 手动断开网络 30 秒后再恢复 | 日志出现"网络已恢复"，无需人工干预 |
| 6.6 | 让电脑休眠 2 分钟再唤醒 | 日志出现"检测到系统休眠/挂起…，立即重新探测网络" |
| 6.7 | 重复双击 `CampusNetService.exe` | 第二个实例立即退出（日志"已有后台实例在运行"），不会双登录 |

## 7. 卸载

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 7.1 | 运行 `CampusNetCLI.exe uninstall` | 打印停止守护、关闭自启动的步骤，全部成功 |
| 7.2 | 检查 `HKCU\...\Run` | `CampusNetDaemon` 已消失 |
| 7.3 | 检查 `%LOCALAPPDATA%\CampusNet` | **仍然存在**（配置与日志默认保留） |
| 7.4 | 再运行 `CampusNetCLI.exe uninstall --remove-data` | 数据目录被删除 |
| 7.5 | 检查旧版残留 | 若曾装过 V2：计划任务 `CampusNetAutoLogin` 与启动文件夹 VBS 都已被清理 |
| 7.6 | 检查杀毒软件设置 | **没有任何变化**（本程序从不修改它） |

## 8. 异常与恢复

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| 8.1 配置损坏 | 把 `config.json` 改成 `{ 坏 JSON` 后启动 | 程序仍能打开并提示配置有问题；**原文件未被删除或覆盖** |
| 8.2 换了 Windows 用户 | 用另一个用户登录后启动 | 提示"密码无法在本机解密，请重新填写"，可重新输入密码 |
| 8.3 安装目录只读 | 把目录设为只读后启动并认证 | 一切功能正常（因为数据写在 `%LOCALAPPDATA%`） |
| 8.4 无网络启动 | 拔网线启动 | 界面正常，提示网络层问题（`unreachable`/`dns-error`），不崩溃 |
| 8.5 安全体检 | 设置页点「安全体检（只读）」 | 显示杀毒软件名称与 Defender 状态，**不会**申请管理员权限、不弹 UAC |
